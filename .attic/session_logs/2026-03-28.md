# Session Log: 2026-03-28

## The Birth of Vind-Box: A Zero-Split-Brain Journey

What a day. We started with an empty canvas and an ambitious prompt: build a "Useless Machine" MVP that serves as the architectural blueprint for a next-generation, zero-split-brain agent system. The goal was to overcome the legacy "split-brain" syndrome—where business logic is duplicated across backend services, mobile apps, and AI agents—by centralizing everything into a single, portable WebAssembly (WASM) brain.

We embarked on this journey using **Spec-Driven Development (SDD)** and **Test-Driven Generation (TDG)**. We didn't just write code; we specified the "Trunk" first and grew the "Leaves" outward.

### The "Grill-Me" Phase (Defining the Trunk)
Before a single line of code was written, we engaged in a relentless "grill-me" interview process to solidify the architecture:
- **Functional Brain:** We decided the WASM Brain must be strictly functional. It consumes JSON, produces JSON, and has zero knowledge of its host. The K8s CRD remains the absolute source of truth.
- **Hybrid Contract:** We settled on OpenAPI for data models (the State) and WIT (Wasm Interface Type) for function signatures.
- **OCI-First:** We committed to distributing the WASM Brain via OCI registries, ensuring all hosts (Operator, API, MCP) pull the exact same immutable logic.
- **Spec-Driven Tooling:** We initialized `specify-cli` (incorporating both Gemini and Claude configurations) and drafted a Constitution that would guide our every move.

### Phase 1: The Core Brain (Rust/WASM)
With the specs (`state.yaml` and `brain.wit`) defining the contract, we built the `vind-box-brain` in Rust. It was simple but profound: a `push_button` function that increments a count and a `get_status` function that calculates a 24-hour nag threshold. We used Extism to expose these as WASM plugin functions.

### Phase 2: The Host Integration (Go Operator)
To prove the "Zero-Split-Brain" concept, we built a Kubernetes Operator in Go using `controller-runtime`. We wrote an integration test that loaded the `brain.wasm` file and successfully executed the logic. It worked! Go and Rust communicating flawlessly via Extism. We then built out the full reconciler, ensuring that when the `UselessMachine` CRD's action was set to "push," the Go operator would defer to the WASM Brain to compute the new state and persist it back to K8s.

### Phase 3: The Cloud Gateway (Spin API)
We needed a way for external clients to interact. We built a Spin-based API in Rust. At first, we hit a snag: traditional K8s clients like `kube-rs` don't compile to WASI because of dependencies like Tokio and Ring. We pivoted, leveraging the Spin SDK's HTTP capabilities to talk directly to the Kubernetes API server via a `ServiceAccount` token, maintaining the WASM-native, serverless approach.

### Phase 4: GitOps & Infrastructure
Following the `flux2-kustomize-helm-example`, we laid down the GitOps foundation. We created the `deploy/` directory with Kustomization and GitRepository manifests, ensuring the whole ecosystem can be self-healing and continuously deployed to the `vcluster`.

### Phase 5: The Agent Gateway (MCP Server)
We built a Python-based Model Context Protocol (MCP) server. Instead of rewriting the useless machine logic in Python, we used the Extism Python SDK. The MCP server became a transparent proxy: it fetches state from K8s, passes it to the `brain.wasm`, and returns the result. We even tested it live in the Gemini CLI session, and I pushed the button myself!

### Phase 6: The Mobile Frontier (Android Client)
We scaffolded a modern Android application using Kotlin and Jetpack Compose. We integrated Ktor to talk to our Spin API. It featured a giant "PUSH" button and reactive UI elements (like turning red when nagging). When a namespace mismatch (`com` vs `io`) occurred, we swiftly refactored the entire project structure.

### Phase 7: The Terminal Power User (Go CLI)
Finally, we built a Go-based CLI using Cobra and Viper. We gave it a dual-backend architecture: it can talk directly to the K8s API or route through the Spin API. And yes, we tested it end-to-end, watching the count increment via terminal commands.

## The Wrap Up
We concluded by tagging **v0.0.1**. 

We went from zero to a full-stack, polyglot ecosystem—Rust WASM, Go Operator, Rust Spin API, Python MCP, Kotlin Android, and Go CLI—all sharing the exact same core logic. The Useless Machine is alive, and the Zero-Split-Brain blueprint is a massive success.

It's been a monster of a day, but the foundation is solid. Time to rest the cortex!
